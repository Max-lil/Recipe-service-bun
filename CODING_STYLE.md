# How To Use This File

If you are helping with code in this project, read this file first and follow it before making changes.

Always prefer:
- simple code
- explicit logic
- minimal abstractions
- beginner-friendly readability

# Coding Style

This project should stay easy to read and easy to learn from.

## Main Rule

Prefer simple and explicit code over clever or advanced solutions.

## What That Means

- Use straightforward code that is easy to follow line by line.
- Match the style already used in the project.
- Prefer small route handlers and clear service functions.
- Avoid advanced TypeScript unless it is really needed.
- Avoid abstractions if a direct solution is easier to understand.
- Keep names clear and practical.
- Write code that feels beginner-friendly.

## Good Defaults

- Prefer simple `if` statements over clever one-liners.
- Prefer repeating a small amount of code if it makes the code easier to read.
- Keep validation and request handling easy to trace.
- Keep functions focused on one job.
- Use comments sparingly, only when they truly help.

## Goal

Anyone working in this project should be able to read the code and understand what it does without needing advanced TypeScript knowledge.
